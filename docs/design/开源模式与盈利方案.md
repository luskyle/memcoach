# 记忆教练：开源模式与盈利方案

> 决策问题：记忆教练是否开源？哪些开源、哪些闭源？开源了怎么赚钱？
> 结论先行：**核心代码开源（AGPL-3.0）+ 服务与商店版收费 = "Anki 的信任 × Readwise 的商业模式 × Obsidian 的心智"**——开源不是放弃收入，是把"隐私信任"变成获客武器、把"服务便利"变成付费理由。

## 一、为什么开源对记忆教练是加分项

| 维度 | 闭源（原本设计） | 开源后的增益 |
| --- | --- | --- |
| 隐私信任 | 靠文案承诺 | **代码可审计 = 数据隐私的硬背书**（记忆工具用户最敏感） |
| 获客 | 口碑 + ASO | GitHub/开发者社区引流（工具赛道天然闭环），star 即势能 |
| 生态 | 无 | 社区贡献词库/插件/翻译；Anki 兼容放大器 |
| 护城河 | 服务器数据 | 社区版与数据集生态，抄代码容易抄不走近用户 |
| 对抗大厂 | 弱 | "你的数据存自己电脑"的开源叙事，差异化拉满 |

> 对标事实：Anki（开源 AGPL）证明记忆工具开源也不妨碍收费；Obsidian（不开源但核心免费）证明"核心免费+服务收费"用户买账。

## 二、开源四模式与记忆教练的选型

| 模式 | 说明 | 代表 | 对记忆教练 |
| --- | --- | --- | --- |
| A 完全开源 | 全部代码公开，服务收费/捐赠 | Anki、Linux | 服务器代码也开源=少一层收入 |
| **B Open Core（本方案）** | **核心开源，商业附加闭源** | GitLab、Ghost | **核心可用免费，Pro 服务收费** ✅ |
| C Source Available | 可看不可自由用（SSPL/RSAL） | Elasticsearch | 社区反感、中文开发者陌生 |
| D 双授权 | 开源版 + 商业许可版 | Qt | B 端出现后再考虑 |

**记忆教练选型 = B（Open Core）+ 商店授权（Anki 模式）**：
- 开源核心：客户端 App、SRS 引擎、卡格式、词库脚本（个人自托管完全可用）
- 闭源服务层：AI 成卡服务、云同步服务器、商店正式版（与开源版同源，但含 Pro 能力）

## 三、开什么 / 闭什么（边界清单）

### 3.1 开源（进 GitHub repo：memcoach）

| 模块 | 说明 | 理由 |
| --- | --- | --- |
| Flutter 客户端（三 Tab/闪卡/记忆库/设置） | 移动端完整 UI 代码 | 开源主战场：信任 + 社区贡献 UI |
| SRS 引擎（SM-2→FSRS 纯函数） | 记忆算法 | **本来就不是秘密**（SuperMemo 论文 + Anki 开源），开源没损失 |
| 卡数据结构与 Anki 兼容层 | .apkg 导入导出 | 协议公开也是生态标准 |
| 词库构建脚本（JLPT/COCA 清洗） | Python 管线 | 公版数据处理，开源壮大数据集 |
| 文档/Wiki（含本整套调研） | 产品与技术决策 | 吸引同频开发者 |

### 3.2 闭源 / 专有（商业层，不进 repo）

| 模块 | 说明 | 为什么能收费 |
| --- | --- | --- |
| AI 成卡服务端（LLM 编排/缓存/质控） | 调 API 有真实成本 | 自托管用户用不了（或限量）——服务型付费 |
| 云同步服务器（多设备 C 档） | Supabase/自建 | 便利性付费（同 Obsidian Sync） |
| 商店正式版（iOS/Android 应用商店） | 打包签名、审核、自动更新 | 便利性付费（同 Anki iOS $25） |
| Pro 功能开关 | OCR 无限额、AI 额度、高级导出 | 随订阅解锁 |
| 品牌资产（logo/图标/商店物料） | — | 品牌即识别 |
| 内容包（词库市场，远期） | 付费记忆集 | 内容市场分成 |

> **边界原则一句话**："一个人能自托管跑起来的"= 开源；"要服务器、要钱、要便利"= 闭源服务。

## 四、盈利五通道与数字估算

| 通道 | 模式 | 定价 | 说明 |
| --- | --- | --- | --- |
| ① Pro 订阅（主收入） | 开源核心 + Pro 解锁 | 25 元/月 · 198 元/年（出海 $4.99/$29.99） | AI 成卡额度、云同步、OCR 无限、多设备优先 |
| ② 商店正式版 | 开源代码 + 官方打包 | App Store 内购（与①同档，长按商店购买） | "不想自己编译"的便利费（Anki 已验证） |
| ③ 云同步托管 | Pro 内含 / 单独档 | 可并入 ① | 数据存用户云盘为主，官方同步为增值 |
| ④ 企业/教育授权 | AGPL 商业豁免 | 按量报价（1~10 万/年） | 机构要私有嵌入/改造时的双授权收入 |
| ⑤ 捐赠/赞助 | GitHub Sponsors/OpenCollective | 自愿 | 补充，不作预期 |

**数字估算（开源放大效应）**：
- 假设开源带来：GitHub 1k~5k star → 商店自然下载 +20~50%（开发者圈层传播）
- 付费转化假设不变（1.5~3%）：**开源帮助的是下载量侧，付费率靠 Pro 价值而非开源与否**
- 自托管流失收入估计：<5%（目标用户是要"用完即走"的移动用户，不搭服务器）
- **结论**：开源预计收入 **净增而非净减**——流失的自托管用户本来也不太可能订阅；多出来的下载与信任是纯增量。

## 六、许可证决策

| 候选 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **AGPL-3.0** | 网络服务也强制开源（防大厂白嫖）；Anki 同款，社区熟悉 | 对企业使用不友好（可能逼走 B 端） | **主选（核心 repo）** |
| Apache-2.0 | 宽松、企业友好、社区最大 | 别人可拿去做闭源竞品 | 备选（若重社区轻防御） |
| MIT | 最宽松 | 同 Apache 且更无约束 | 不用 |

**最终方案：核心 repo 用 AGPL-3.0；同时提供商业授权条款（出售 AGPL 豁免给企业）→ 与双授权天然衔接（盈利通道④）。**

> 一致性提示：AGPL 与"Anki 兼容"也自洽——Anki 本身 AGPL，互相借鉴无障碍。

## 七、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Fork 做闭源竞品 | 开源界常态 | AGPL 防"服务端白嫖"；差异化在服务层与生态，不在代码本身 |
| 自托管分流收入 | <5% | 目标用户不搭服务器；Pro 卖"便利+AI"而非"功能" |
| 社区义务挤占开发时间 | 单人最怕 | **设边界**：CONTRIBUTING 写明只接收小 PR/翻译/词库；大功能走 issue 讨论 |
| 商店审核"开源+订阅"矛盾 | 中 | Anki 先例充分；商店版与开源版用不同 bundle id 即可规避混淆 |
| 暴露 AI 成本结构 | 低 | 服务层闭源；开源版限本地算法，AI 能力天然在服务端 |

## 八、落地节奏与仓库结构

### 8.1 仓库结构（沿用已建好的 github.com/luskyle/memcoach 私有仓）

```
memcoach/
  app/            # Flutter 客户端（开源 AGPL）
  engine/         # SRS 纯函数（开源 AGPL，独立可测）
  tools/          # 词库管线脚本（开源）
  docs/           # 本整套调研文档（开源）
  server/         # 云同步/AI 服务（此目录进入 .gitignore 的私有子仓或独立私有仓）
  LICENSE         # AGPL-3.0
```

### 8.2 开源节奏（结合开发计划）

| 时间 | 动作 |
| --- | --- |
| W1~6（开发期） | 私有仓开发（当前状态），commit 全量历史 |
| W7~9 | 决定许可证（默认 AGPL）+ 拆分 server 目录；编写 LICENSE/CONTRIBUTING/README |
| W10（上架同步） | **repo 转 public**（私有→公开），发布 v0.1 标签；商店版用另一 bundle id |
| W11+ | GitHub Discussions 开社区；翻译/词库 PR 收割 |

> 为什么 W10 才公开：先跑通验证与收入闭环，再迎开源流量；避免"开局即开源却无产品"的冷淡。

## 结论

> **开源不是慈善，是记忆教练的获客策略与信任背书；闭源不是贪婪，是服务层的合理收费。**
> 一张表总结：**核心引擎与客户端开源（AGPL）→ 信任与生态；AI/云同步/官方打包闭源收费 → 收入来源；商店版 = Anki 式便利费；企业豁免 = 远期 B 端。**
> 预期效果：下载量靠开源放大、付费率靠 Pro 价值、护城河靠生态与数据**——开源让记忆教练"小"但有分量，这正是独立开发者对抗巨头的唯一姿势。**
