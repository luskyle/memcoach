## 一、定位与设计原则

### 1.1 一句话定位

> **把你想记住的任何东西——单词、摘抄、灵感、考纲——划进收件箱，App 用间隔重复自动安排复习，直到你真正记住。**

### 1.2 设计原则（对应《实用化转型》）

1. **三 Tab 常驻**：结构永远不变，肌肉记忆，不做隐藏入口。
2. **复习页是主角**：打开 App 默认落点 = 今日复习。
3. **动效只做反馈不做表演**：翻卡、打卡、曲线更新有微反馈，无粒子、无吉祥物。
4. **数据说话**：成长感全部来自真实数据（曲线、热力图、月度报告）。
5. **隐私默认**：本地优先，不登录可完整体验，导出/删除一键。
6. **键盘友好**：桌面端全键盘可操作。

## 二、信息架构：三 Tab + 一条管道

```
                     ┌──────────────────────────────┐
  输入管道（收藏入口）  │ ① 收件箱 —— 待整理/待学习      │
  分享面板 / 剪贴板    │ ② 复习 —— 今日任务（默认落点） │
  / 拍照OCR / 手录    │ ③ 记忆库 —— 全部卡片，可筛选   │
                     └──────────────────────────────┘
```

| Tab | 职责 | 关键交互 |
| --- | --- | --- |
| 收件箱 | 收藏入口与待整理区 | 列表 = 收藏时间倒序；卡片显示"已成卡/待归类"；一键整理（AI 打标建议） |
| 复习 | 今天该复习的内容 | 今日任务数 + 大按钮开始复习；遗忘曲线入口；中途可退出（自动保存进度） |
| 记忆库 | 全部卡片的管理 | 全局搜索；筛选（语言/主题/来源/状态/掌握度）；文件夹 + 平铺双视图 |

- 全局共享元素：顶部搜索栏（跨 Tab）、底部三 Tab、右上角"+"（快速收藏/手录）。

## 三、六大核心模块

| 模块 | 职责 | 对应技术调研结论 |
| --- | --- | --- |
| 收藏管道 | 四个输入入口 + 去重 + 压缩 | 分享面板（系统级）、剪贴板监听、拍照 OCR、手动输入 |
| 成卡引擎 | 收藏 → 可复习卡片（AI 补释义/例句/发音，可全改） | LLM 批量/低频 + 离线词库兜底 |
| 复习引擎 | SRS 调度 + 闪卡交互 + 三键评级 | 本地 SM-2 → FSRS（纯函数，可单测） |
| 记忆库 | 检索/过滤/分组 + 统计 | drift 本地 SQL |
| 统计与报告 | 遗忘曲线、热力图、月度报告 | review_log 派生（投影） |
| 同步订阅 | 云同步（可选）+ 订阅墙 | 存储 A/B/C 档；本地优先 |

## 四、核心数据流

```
收藏（分享/粘贴/拍照/手录）
  → 去重/压缩 → 收件箱条目
  → AI 成卡（补词条/例句/发音；可编辑）
  → 进入记忆库 + 首次复习排期（SRS）
  → 每日复习队列（三键评级写 review_log）
  → SM-2 更新间隔 → 遗忘曲线/热力图/月报 → 薄弱项加权
  →（可选）用户云盘增量备份 / 云端日志同步
```

## 五、投影原则：状态从数据派生

**铁律（沿用游戏版架构的核心遗产）**：一切"状态"（已掌握/待复习/薄弱/热力图）都是 `review_log` + `items` 的**派生投影**，实时计算、可重算、可回滚。

```
review_log + items（唯一事实来源）
      │ 派生（本地缓存可失效）
      ▼
统计投影：掌握度 / 复习曲线 / 薄弱分类 / 热力图
```

- 好处 1：用户无法"假装学会"（打卡可以作弊，但曲线会说实话）。
- 好处 2：同步修复 = 日志回放（append-only），架构简单可靠（沿用存储方案 C 档）。

## 六、数据模型

```sql
-- 内容域
words(id, lang, headword, reading, ipa, audio_file, level, tags)   -- 词条（官方词库）
cards(id, word_id, kind, prompt, answer, ...)                      -- 卡片（SRS 对象）

-- 收藏域（工具版核心）
items(
  id, card_id,               -- 收藏条目 → 卡片（成卡后可空）
  source,                    -- share | clipboard | photo | manual | anki_import
  media_path,                -- 本地压缩后媒体（不符用户云盘）
  original_url,              -- 剪藏引用（不托管原文）
  note,                      -- 用户备注（为什么收）
  status,                    -- inbox | pending_tag | learning | mastered（投影缓存）
  created_at
)

-- 学习域（与架构 7.x 一致）
review_log(id, card_id, user_id, reviewed_at, quality, interval_days, ease_factor, state, source)
collections(id, name, parent_id)      -- 记忆库分组（用户自建，替代"馆"）
item_collection(item_id, collection_id) -- 多对多
-- 游戏域（已删除：无 furniture/palace，无稀有度/皮肤）
```

> 删除项说明：`furniture` / `palace` / 稀有度 / 皮肤 / 体力 —— 全部随游戏化一起移除；**items 直接取代"藏品"概念**，无游戏包装。

## 七、技术分层

```
┌──────────────────────────────────────────────┐
│ 客户端（Flutter，离线优先）                     │
│  表现层：三 Tab UI / 闪卡 / 曲线图表（fl_chart）│
│  领域层：SRS 引擎 / 成卡引擎 / 分类打标         │
│  数据层：drift（SQLite）/ 本地文件 / Hive 缓存   │
└──────────────┬───────────────────────────────┘
               │ 同步三态：无 / 用户云盘 / 云端日志
┌──────────────▼───────────────────────────────┐
│ 后端（极小）                                   │
│  可选 Supabase（账号+日志+索引，免费档内）        │
│  或自建轻量服务器（50~100 元/月）                │
│  ——永远没有媒体文件上传接口（存储方案铁律）        │
└──────────────────────────────────────────────┘
```

- 技术选型全量沿用《技术调研-核心技术选型》：Flutter、drift、SM-2→FSRS、TTS 离线包、本地通知。
- 新增组件极少：OCR（系统 API / mlkit）、分享面板接收（平台通道）、图表（fl_chart）、WebDAV/iCloud 通道。

## 九、与游戏版架构的本质差异

| 维度 | 游戏版（已归档） | 拾忆工具版 |
| --- | --- | --- |
| 核心场景 | 宫殿/家具/展柜 | 收件箱/复习队列/记忆库 |
| 输入 | 课程远征 | 全局收藏管道（任何 App 划进来） |
| 激励 | 游戏反馈（连击/盲盒） | 真实数据（曲线/月报/热力图） |
| 游戏数据 | furniture/palace/皮肤 | **无**（全部删除） |
| 美术依赖 | 高 | **零** |
| 多端 | 移动优先 | 移动优先 + 桌面端（Flutter 天然） |
| 成败关键 | 内容产能 | 体验流畅度 + 数据可信度 |

> **一句话架构**：三 Tab 永远不变，管道负责"进"，引擎负责"记"，数据负责"证明"——拾忆是一个把「收藏 → 复习 → 证明」三件事做得无可挑剔的工具。
